# 워치 러닝 상세 센서 기록

휴대폰과 워치 앱을 모두 업데이트한 뒤 시작한 러닝부터 적용됩니다. 별도 목표 설정은 없습니다. 기존 위치·활동 인식·심박 권한을 사용하며 추가 서버나 계정으로 보내지 않습니다. 상세 데이터는 앱 내부 및 폰-워치 Data Layer에만 보관합니다. 기존 Health Connect 전송 범위는 확대하지 않습니다.

## 수집과 시간

- Health Services에서 RUNNING의 지원 항목을 조회하고 교집합만 요청합니다. 심박/심박 통계·속도·거리·칼로리·걸음 수·케이던스·절대 고도·누적 상승/하강이 대상입니다. 미지원 항목과 지원하지만 샘플이 없는 경우를 구분할 수 있습니다.
- 화면이 꺼져 묶여 전달되어도 각 샘플의 원래 측정 시각을 모두 보존합니다. 배터리 소모를 늘리는 강제 고빈도 전달 모드를 켜지 않습니다. 수집 간격과 정확도는 기기/센서 상태에 따라 다르며 매초 수신을 보장하지 않습니다.
- 심박 정확도, 센서 가용성, 사용자 일시정지·재개·종료 요청, 수신한 실제 운동 상태, 활동 시간 체크포인트를 저장합니다. 상태 이벤트 시각은 수신 시각이지 시스템 내부 전환 시각이 아닙니다.
- 1km 통과를 관측했을 때와 종료 시 시스템 랩을 요청해 실제 구간 시작/끝·활동 시간·거리·심박 통계를 지원 범위에서 보존합니다. 배치 수신으로 구간 거리가 정확히 1km가 아닐 수 있으며, 정확히 1km였다고 추정해서 바꾸지 않습니다. 마지막 부분 구간도 보존합니다.
- 기존 GPS 요청에서 위도·경도·고도·수평/수직 정확도·속도·방향을 함께 보관합니다. 정밀도가 낮은 점도 원본 분석용에는 표시해서 남기되 기존 지도 경로 필터는 유지합니다. 오래되거나 시각이 잘못된 GPS 점은 사용하지 않습니다.
- UTC는 수집 시작 시 기기의 벽시계와 부팅 후 경과 시간을 연결한 값입니다. 워치 시계가 틀려 있으면 절대 시각도 틀릴 수 있습니다. 센서 활동 시간과 GPS 경로 활동 시간은 다른 원점일 수 있습니다.

## 저장·동기화·백업

- 워치 내부 비공개 폴더에 배치를 순서대로 추가 저장합니다. UI 메모리에서 지난 샘플을 버리지 않으며, 프로세스 재생성 후에도 저장된 파일을 읽어 종료할 수 있습니다. 비정상 종료 중 마지막 쓰기가 손상된 경우 무손실 복구를 보장하지 않습니다.
- 정상 종료 시 마지막 센서 업데이트를 기다립니다. 10초 내 최종 업데이트가 오지 않는 등 문제가 있으면 `quality` 이벤트로 남겨 부분 수집임을 알 수 있습니다. 파일 저장 실패 시 완료 처리하지 않고 재시도할 수 있게 유지합니다.
- 전체 완료 기록은 gzip Asset으로 전달합니다(일반 DataItem의 100 KB 제한 회피). 폰이 없으면 Data Layer 대기열에 유지되고, 폰은 DB 저장 성공 후에만 확인 삭제합니다. 앱을 다시 열 때 미처리 대기열을 재조회합니다. 워치 임시 파일은 Data Layer 저장 성공 후 정리합니다.
- 휴대폰 DB의 5→6 마이그레이션에서 기존 기록을 지우지 않고 센서 저장을 추가했으며, 현재 v7에서도 유지합니다. 작은 센서 요약은 세션에, 전체 시계열은 32,000자씩 나눈 별도 행에 저장하여 Android의 큰 행 제한을 피합니다. 해당 러닝 삭제 시 센서 원본도 삭제됩니다.
- JSON 백업 v5는 센서 청크와 인바디 CSV 원본까지 복원합니다. 분석용 v3에는 청크를 해독한 `sensorTelemetry`와 `sensorSummary`가 있습니다. 기존 v1~v4 백업 및 워치 v4 완료 기록도 읽습니다. 새 Asset을 이해하지 못하는 구버전 폰에서는 폰 업데이트 전까지 수신되지 않습니다.

## 화면과 해석

워치에는 케이던스·누적 상승을 지원할 때 표시합니다. 폰 `러닝 기록`의 펼친 상세에는 심박 최소/최대·샘플 수, 케이던스, 걸음, 상승/하강, 절대 bpm 범위별 측정 시간을 표시합니다. 상세 원본 시계열은 JSON에서 분석합니다. 개인별 최대심박이나 의료적 운동 강도를 임의로 추정하지 않습니다.
