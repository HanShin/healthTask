# 상세 분석 JSON 내보내기

`설정 → JSON 백업 → 상세 데이터 내보내기 (JSON)`에서 하나의 JSON 파일로 저장합니다. 현재 휴대폰 DB의 전체 기간을 읽으며, 기간 제한·GPS 단순화·샘플 개수 제한을 두지 않습니다. 파일 생성 과정에서 기록을 변경하거나 외부 서버로 전송하지 않습니다.

## 파일 구성

최상위 `schemaVersion: 5`와 기존 필드, `runTelemetryChunks`, `inBodyRecords`는 복원용 원본입니다. 로컬·워치·이전 앱 기록과 보관 중인 과거 근력 데이터도 기존처럼 유지합니다. `analysis` 영역은 `schemaVersion: 3`인 읽기 전용 분석 자료이며, 백업 불러오기에서는 무시합니다. 따라서 외부 캐시나 분석용 파생 수치가 로컬 기록으로 다시 들어가지 않습니다. v1~v4 백업도 계속 읽으며, v3 이하 백업으로 같은 ID의 기록을 복원할 때 이미 저장된 상세 센서를 삭제하지 않습니다.

| 분석 영역 | 포함 정보 |
| --- | --- |
| `metadata` | 내보낸 UTC 시각·시간대, 앱 버전, 저장/연동 기록 개수, 수집 범위 |
| `fieldGuide`, `sourceCodes`, `notes` | 단위·계산 기준·시간 해석·출처 코드·누락/개인정보 주의사항 |
| `runningSessions[].record` | 원본 세션 및 운동 항목·세트. 날짜·시작/종료·거리·활동 시간·평균 심박·칼로리·메모·출처 패키지·외부 ID·생성/수정 시각·동기화 상태/오류·압축 경로/랩 문자열 |
| `runningSessions[].calculations` | 단위 변환 거리, 활동/벽시계 시간, 비활동 시간 차이, 계산한 평균 페이스(s/km)·속도(km/h), 사용한 원본 필드 |
| `runningSessions[].routePoints` | 전체 유효 GPS 점의 위도·경도·활동 경과 시간·원본 내 순번 |
| `runningSessions[].laps` | 저장된 구간별 거리·소요 시간·활동 시간 기준 시작/끝·계산 페이스·1km 여부. 마지막 미완성 구간도 포함 |
| `runningSessions[].dataQuality` | 경로/랩 원본·유효·해독 실패 개수, GPS 시간 순서, 비정상 날짜·거리·시간 경고 |
| `runningSessions[].sensorTelemetry` | 새 워치의 측정 시각별 전체 심박·속도·케이던스·걸음·고도·상승/하강·칼로리·거리, GPS 정확도 및 센서/상태 이벤트. 기기 지원 범위와 시간 기준 포함 |
| `runningSessions[].sensorSummary` | 심박 최소/최대·샘플 평균, 케이던스·걸음·상승/하강·고도 요약, 절대 bpm 범위별 확인된 측정 시간과 측정 범위 |
| `summary`, `dailySummaries`, `weeklySummaries`, `monthlySummaries` | 중복을 제외한 러닝 수·알려진 거리/활동 시간/벽시계 시간/칼로리 합계, 측정값 존재 개수와 거리 가중 평균 활동 페이스 |
| `bodyMeasurements` | 저장된 모든 체성분 측정. 지표명·값·단위·날짜·시각·출처·외부 ID, 같은 날 같은 항목의 기록 수. 여러 출처의 값과 예전 체수분 값도 보존 |
| `inBodyRecords` | CSV 원본 현지 측정 시각·선택한 시간대·UTC 시각·측정장비·최초 파일명·전체 원본 열/문자열. 미지원 항목·미측정 표시도 보존. `bodyMeasurements.externalRecordId`로 연결 |
| `workoutLinks` | 로컬/외부 중복 연결 ID·시간 중첩 비율·연결 시각 |
| `cachedExternalWorkouts` | 현재 폰에 동기화된 외부 운동 캐시 원본. 복원하지 않음 |
| `unavailableMeasurements` | 현재 저장하지 않는 항목 목록 |

## 올바르게 분석하는 방법

- 일반 집계는 `includedInSummary: true`인 러닝만 사용합니다. 완료/부분 완료 기록이며, 같은 운동으로 연결된 외부 기록은 `duplicateOfSessionId`로 표시하고 제외합니다. 원본 자체는 내보내기에서 삭제하지 않습니다. 자동 연결되지 않은 중복은 남을 수 있으므로 다른 출처의 같은 시간대 기록도 확인하세요.
- `null`은 알 수 없다는 뜻입니다. 측정된 0과 다릅니다. 합계는 값이 있는 기록만 더하고 coverage 개수를 함께 제공합니다. 모든 값이 없으면 합계도 `null`입니다.
- 평균 페이스의 `paceDurationBasis`가 `activeDurationMillis`이면 저장된 활동 시간, `wallClockDurationMillis`이면 시작~종료 전체 시간입니다. 외부 기록의 전체 시간을 휴식 제외 시간으로 해석하지 마세요.
- 전체 평균 활동 페이스는 거리와 활동 시간이 모두 있는 기록만 사용해 **활동 시간 합계 ÷ 거리 합계**로 계산합니다. 개별 페이스의 단순 평균이 아닙니다. 일부 운동 항목의 거리만 있을 때는 이를 전체 세션 거리로 추정하지 않습니다.
- `nonActiveDurationMillis`는 벽시계 시간에서 활동 시간을 뺀 값입니다. 일시정지뿐 아니라 대기나 기기 시계 차이도 포함할 수 있으므로 실제 정지 횟수나 정지 구간을 뜻하지 않습니다.
- 날짜별 집계는 저장된 `sessionDate` 기준, 주간 집계는 월요일 시작입니다. 유효하지 않은 날짜는 원본과 전체 집계에 남지만 날짜별 집계에서는 제외하고 경고합니다.
- 인바디는 같은 날짜·항목에 여러 값이 있어도 하나로 덮거나 평균 내지 않습니다. 출처와 측정 시각을 보고 분석 목적에 맞는 값을 선택하세요.

## 시간과 위치의 한계

원본 타임스탬프는 Unix 밀리초입니다. UTC 문자열과 내보낸 시점의 시간대로 바꾼 문자열을 함께 제공합니다. **내보내기 시간대는 러닝 당시의 시간대가 아닙니다.** 새 워치의 `sensorTelemetry.metadata.timeZoneId`는 수집 시작 당시 시간대입니다. `sensorTelemetry.records.timestampEpochMillis`는 기기 시계 기준 실제 센서 측정 시각이며, `elapsedRealtimeMillis`는 부팅 후 단조 증가 시각입니다. 이벤트의 시각은 사용자 요청/상태 수신 시각입니다. 기존 `routePoints` 및 과거 기록에는 이런 시각·시간대가 없습니다.

경로의 `activeElapsedMillis`는 각 기록 기기의 활동 시간 축이며 일시정지 시간을 포함하지 않습니다. `startedAt + activeElapsedMillis`를 GPS 점의 실제 UTC 시각으로 사용하면 안 됩니다. 휴대폰과 워치의 활동 시간 원점도 약간 다를 수 있습니다. 위도·경도는 WGS84 도 단위이며 원본 순서를 유지합니다.

새 워치 기록의 `sensorTelemetry`는 지원 센서에서 받은 모든 시계열을 포함합니다. 속도(m/s)가 양수인 경우 페이스(s/km)는 `1000 / speedMetersPerSecond`로 계산할 수 있습니다. 거리·칼로리·걸음·상승/하강 누적값은 시간별 스냅샷이므로 합산하지 말고 마지막 값을 사용하세요. 심박 범위는 개인 최대심박 기반 운동 강도 구간이 아니라 절대 bpm 구간입니다. 최대 5초 이내의 연속 샘플 중 활동 시간 증가가 확인된 부분만 집계하며, 마지막 샘플 이후와 측정 공백은 채우지 않습니다. `heartRateBandCoveredMillis`로 실제 집계 범위를 확인하세요. 샘플 평균은 기기의 공식 시간 가중 평균과 다를 수 있습니다.

지원하지 않는 센서, 기존 기록, 폰 단독 러닝의 상세 심박/케이던스는 추정하지 않습니다. GPS 고도와 Health Services 고도는 기준·오차가 다를 수 있으며 임의로 합쳐 상승량을 만들지 않습니다. 날씨·VO₂max·개인별 심박 존·혈압·심전도·산소포화도는 이번 수집 대상이 아닙니다. 워치의 저장되지 않은 랩도 경로에서 임의 생성하지 않습니다. 캡처 원본 이미지는 저장/내보내지 않습니다.

현재 휴대폰에 도착하지 않은 워치 기록, 외부 앱에서 아직 읽지 않은 기록, 진행 중 트래커의 메모리 상태는 대상이 아닙니다. 운동 종료 및 동기화를 마친 뒤 내보내세요. 저장된 옛 압축 경로/랩에 해독 실패 항목이 있으면 원본 문자열은 보존하고 유효 항목과 실패 개수를 따로 제공합니다.

## 개인정보

JSON은 암호화하지 않습니다. 정확한 이동 경로·운동 시간·건강 수치·메모가 들어 있습니다. AI 분석 서비스 등에 업로드할 때는 포함 범위를 확인하세요. 위치는 원본 `routePolyline`, 분석용 `routePoints`, 상세 센서 `sensorTelemetry` 및 복원용 `runTelemetryChunks`에도 있으므로 경로 한 필드만 지워서는 익명화되지 않습니다. 외부 운동 원본에도 위치 문자열이 있을 수 있습니다.
